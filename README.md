# AudioNotes / ЛекторКонспект

Мобильное приложение для Android: записывает лекцию, локально распознаёт речь и превращает её
в структурированный Markdown-конспект с формулами LaTeX через LLM.

Реализация ведётся по [PRD.md](PRD.md).

---

## Стек

| Слой | Технология |
|------|------------|
| Язык / UI | Kotlin, Jetpack Compose, Material 3 |
| Архитектура | MVVM (`AppViewModel` + `StateFlow`), ручной DI через `ServiceLocator` |
| Хранилище | Room (метаданные и тексты) + файловая система (`files/audio/*.m4a`) |
| Запись | `MediaRecorder` в foreground-сервисе, AAC/M4A, 44.1 кГц, 128 кбит/с — на 5-часовые сессии |
| Распознавание | `SpeechRecognizer` (on-device на Android 12+, обычный — ниже) |
| LLM | OpenAI-совместимый API (`/chat/completions`), Retrofit + kotlinx.serialization |
| Рендеринг `.md` | WebView + локальные `marked.js` и `MathJax` (без интернета) |
| Настройки | DataStore Preferences (тема, провайдер, ключ, модель, адрес сервера) |

* **Android SDK** — `C:\Android\Sdk`

  * `platform-tools` (adb)
  * `cmdline-tools;latest`

* **Android Studio** — `C:\Program Files\Android\Android Studio`

Переменные окружения (`JAVA_HOME`, `ANDROID_HOME`, `ANDROID_SDK_ROOT`, `Path`) уже прописаны
в пользовательском окружении Windows. Для текущей сессии PowerShell может потребоваться
переоткрыть терминал.

> Проект лежит в папке с кириллицей в пути. AGP на Windows такие пути не поддерживает,
> поэтому в `gradle.properties` включён флаг `android.overridePathCheck=true`.
> Сборка и установка APK при этом работают, а вот Gradle-воркер юнит-тестов
> не может загрузить классы из не-ASCII пути (падает `ClassNotFoundException`).
> Поэтому тесты запускаются из ASCII-пути — см. раздел «Проверка».

## Запуск

1. Установить приложение и открыть **Настройки → LLM-провайдер**:
   * выбрать провайдера (по умолчанию — **Cloudflare Workers AI**: 10 000 нейронов в сутки
     бесплатно, карта не нужна, из России работает);
   * нажать «Где взять ключ» — откроется консоль провайдера, где ключ выдаётся бесплатно;
   * вставить ключ в поле «API-ключ»;
   * нажать **«Сохранить»** (или просто увести фокус — сохранится автоматически);
   * нажать **«Проверить подключение»** — приложение сделает тестовый запрос и покажет `OK` или текст ошибки.

   Ключ можно вводить, менять и очищать сколько угодно: поле остаётся редактируемым,
   под ним показывается статус — «Ключ не задан» / «Есть несохранённые изменения» /
   «Ключ сохранён на устройстве». Иконка 👁 показывает ключ, корзина очищает его.

   Ключ хранится локально в DataStore на устройстве и в git не попадает.
   Если генерация упала с ошибкой про ключ, на экране «Обработка» появится кнопка
   **«Настройки»** — она открывает нужный экран в один тап.

   Свой сервер с нейросетью (Ollama, vLLM, LM Studio) подключается без ключа —
   см. раздел «Подключение к своему серверу».

2. При желании задать провайдера по умолчанию для сборки — в `local.properties`:

   ```properties
   sdk.dir=C\:\\Android\\Sdk
   llm.provider=cloudflare
   llm.api.key=
   llm.model=
   llm.endpoint=
   ```

   Файл в `.gitignore`, в репозитории лежит шаблон `local.properties.example`.
   Пустой `llm.api.key` означает «брать ключ из настроек приложения».
   `llm.endpoint` — Account ID для Cloudflare либо адрес своего сервера.

3. Собрать и установить на устройство/эмулятор:

   ```powershell
   cd C:\Users\admin\Documents\ЧЕКТОМОР\AudioNotes
   .\gradlew.bat :app:assembleDebug
   .\gradlew.bat :app:installDebug
   ```

4. В Android Studio: **File → Open** → указать корневую папку проекта.
   Студия подхватит тот же Gradle Wrapper.

## Подключение к своему серверу с нейросетью

Если нейросеть крутится на вашем сервере (Ollama, vLLM, LM Studio, llama.cpp, TGI) —
выберите провайдера **«Свой сервер (OpenAI-совместимый)»** и укажите адрес:

1. **Настройки → LLM-провайдер → Свой сервер (OpenAI-совместимый)**.
2. В поле **«Адрес сервера»** укажите адрес API, например:
   * `http://192.168.1.10:11434` — Ollama;
   * `http://server.local:8000` — vLLM;
   * `http://192.168.1.10:1234/v1` — LM Studio.

   Схему можно не писать — добавится `http://`. Путь `/v1` добавляется сам, если он
   не указан явно. Свой адрес приложение помнит и не стирает при переключении
   провайдеров туда-обратно.
3. **API-ключ не нужен** — поле остаётся пустым, заголовок `Authorization` не отправляется.
   Если сервер всё же требует ключ, вставьте его.
4. Нажмите **«Загрузить модели с сервера»** — приложение сделает `GET /v1/models`
   и покажет список доступных моделей (`qwen2.5:7b`, `llama3.1:8b` и т. п.). Выберите
   нужную из выпадающего списка или впишите название вручную — для своего сервера
   модель обязательна.
5. **«Проверить подключение»** — тестовый запрос к `POST /v1/chat/completions`.

Важно знать:

* Телефон и сервер должны быть в одной сети (Wi-Fi) либо сервер должен иметь белый IP.
* Обычный `http` внутри локальной сети разрешён: в `res/xml/network_security_config.xml`
  включён `cleartextTrafficPermitted`, иначе Android 9+ обрывал бы такие соединения.
* Промпты приложения длинные — выбирайте модель с контекстом хотя бы 8k токенов,
  иначе конспект будет обрезаться (см. раздел «Как устроена генерация конспекта»).
* Обращение идёт по протоколу OpenAI (`/v1/chat/completions`), поэтому подойдёт любой
  сервер, который этот протокол поддерживает.

## Сценарий работы

1. **Главный экран** — большая круглая кнопка микрофона, таймер, счётчик распознанных символов.
   Слева вверху — история, справа вверху — настройки.
2. **Стоп** — диалог «Какая это была лекция?»: *Точные науки* или *Гуманитарные науки*
   (влияет на системный промпт).
3. **Обработка** — два шага: «Распознавание аудио…» → «Генерация конспекта…».
   После распознавания можно нажать «Проверить текст», поправить формулы и термины вручную
   (PRD, раздел 10) и продолжить.
4. **Результат** — конспект с отрисованными формулами LaTeX. Панель действий:
   * ⬇ — сохранить `.md` в «Загрузки»,
   * 🎤 — прослушать исходную запись,
   * **Т** — открыть полный текст расшифровки.
5. **История** — список всех записей с переходом к готовому конспекту.
6. **Настройки** — тёмная тема, выбор LLM-провайдера, API-ключ, модель, адрес сервера,
   проверка подключения, версия приложения.

## Как устроена генерация конспекта

`SummaryGenerator` (app/src/main/java/com/audionotes/app/data/llm/SummaryGenerator.kt):

1. Текст режется на части по ~6000 символов (границы абзацев и предложений сохраняются).
2. Каждая часть уходит в Groq отдельным запросом с системным промптом из PRD (раздел 9).
3. Части объединяются финальным запросом-промптом `MERGE_SYSTEM_PROMPT`.
4. Если суммарный объём частей слишком велик, объединение выполняется итеративно
   (группы по 4, затем по 6 и т. д.).

Такой подход снимает лимит контекстного окна для 5-часовых лекций.

## Известные ограничения MVP

* **Распознавание речи.** `SpeechRecognizer` работает параллельно с `MediaRecorder`; на части
  устройств второй захват микрофона блокируется системой. Если живой распознаватель не даёт
  текст, после остановки выполняется fallback — разбор уже записанного файла через
  `EXTRA_AUDIO_SOURCE` (Android 12+). Если и он недоступен, приложение сообщает об этом,
  а запись остаётся доступной для прослушивания.
* **Долгие записи** идут в foreground-сервисе (`RecordingService`, тип `microphone`): запись и
  распознавание продолжаются, даже если свернуть приложение или погасить экран. В шторке —
  уведомление с таймером, счётчиком символов и кнопкой «Стоп».
* Таблицы в конспектах не поддерживаются (это требование PRD).
* API-ключ вводится в настройках приложения и хранится в DataStore на устройстве; в коде его
  нет. Переход на backend с серверным ключом — следующий шаг развития.
