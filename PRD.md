# PRD: Мобильное приложение для конспектирования лекций (Android)

## 1. Обзор приложения и цели
**Название проекта:** (Рабочее название) AudioNotes / ЛекторКонспект
**Платформа:** Android (MVP)
**Цель:** Создать мобильное приложение, которое позволяет студентам записывать длительные лекции (до 5 часов), автоматически переводить их в текст локально на устройстве и генерировать краткие, структурированные конспекты в формате `.md` с помощью языковой модели (LLM) через API.

**Проблема:** Студенты не успевают записывать за лектором или не умеют выделять главное из устной речи. 
**Решение:** Приложение берет на себя рутину аудиозаписи, расшифровки и сжатия информации в готовые тезисы.

## 2. Целевая аудитория
* Студенты любых направлений (гуманитарные, технические, естественнонаучные).
* Люди, которым удобнее воспринимать информацию на слух, но нужен текстовый конспект для подготовки.

## 3. Основные функции и функциональность (MVP)
1. **Аудиозапись:** Запись звука с микрофона устройства. Поддержка длительных сессий (до 5 часов).
2. **Выбор типа лекции:** После остановки записи пользователь выбирает категорию: «Точные науки» или «Гуманитарные науки» (влияет на выбор промпта для LLM).
3. **Локальная транскрибация (Аудио -> Текст):** Распознавание речи происходит на устройстве пользователя (без передачи аудио в сеть).
4. **Генерация конспекта:** Отправка полученного текста через API в LLM с соответствующим промптом. Нейросеть возвращает структурированный `.md`-файл. **Обязательно:** поддержка формул (нейросеть должна выдавать их в формате LaTeX).
5. **Доступ к исходникам:** Возможность в любой момент открыть полный текст расшифровки или прослушать оригинальный аудиофайл.
6. **Экспорт:** Сохранение готового конспекта в формате `.md` в папку «Загрузки» устройства.
7. **Настройки:** Переключение темной/светлой темы, просмотр версии приложения.

*(Примечание: Поддержка таблиц в MVP не реализуется).*

## 4. Рекомендации по техническому стеку
* **Язык и среда:** Kotlin, Android Studio.
* **Архитектура:** MVVM (Model-View-ViewModel).
* **Локальное хранилище:** Room Database (для хранения метаданных записей и текстов конспектов), файловая система устройства (для аудиофайлов и `.md`).
* **Транскрибация:** Локальный Android SpeechRecognizer или встроенная легковесная модель (например, Whisper.cpp для Android).
* **Сеть:** Retrofit / Ktor для работы с API нейросети.
* **LLM API:** Выбранный API (например, Groq, Gemini или OpenRouter). Для прототипа API-ключ вшивается в приложение.

## 5. Концептуальная модель данных
**Сущность: `Recording` (Запись)**
* `id`: String (Уникальный идентификатор)
* `title`: String (Название лекции или авто-дата)
* `date`: Date (Дата и время создания)
* `duration`: Long (Длительность в секундах)
* `lectureType`: Enum (EXACT_SCIENCES, HUMANITIES) — тип лекции для выбора промпта
* `audioFilePath`: String (Путь к локальному аудиофайлу)
* `transcript`: String (Полный текст расшифровки)
* `summaryMd`: String (Готовый конспект в формате Markdown)
* `status`: Enum (RECORDING, TRANSCRIBING, GENERATING, COMPLETED, ERROR)

## 6. Принципы дизайна пользовательского интерфейса (UI/UX)
**Цветовая схема:** Темная и светлая темы. Основной акцент на глубокий синий/фиолетовый.

**Экраны:**
1. **Главный экран:** 
   * По центру: большая круглая кнопка с иконкой микрофона (старт/стоп).
   * Левый верхний угол: иконка списка (открывает историю конспектов).
   * Правый верхний угол: иконка шестеренки (настройки).
2. **Экран выбора типа лекции (появляется после нажатия «Стоп»):**
   * Заголовок: «Какая это была лекция?»
   * Две крупные кнопки: «Точные науки» (математика, физика, информатика и т.д.) и «Гуманитарные науки» (история, литература, философия и т.д.).
3. **Экран обработки:** Пошаговый прогресс-бар. 
   * Шаг 1: «Распознавание аудио...» (локально).
   * Шаг 2: «Генерация конспекта...» (отправка в LLM).
   * При ошибке сети: всплывающее окно с кнопкой «Повторить».
4. **Экран результата:**
   * Отображение готового конспекта (с поддержкой рендеринга формул).
   * Панель действий (иконки):
     * *Стрелка вниз*: Сохранить в `.md` в «Загрузки».
     * *Микрофон*: Воспроизвести аудиозапись.
     * *Буква «Т»*: Открыть полный текст расшифровки.

## 7. Соображения по безопасности и конфиденциальности
* **Аудио:** Хранится исключительно на устройстве пользователя. Не передается на сторонние серверы.
* **Текст:** Передается в API нейросети только для генерации конспекта.
* **Прототип (MVP):** API-ключ вшит в код приложения. Это сделано исключительно для демонстрации.
* **Будущее:** Переход на архитектуру с backend-сервером для скрытия API-ключей, либо внедрение возможности ввода пользователем своего ключа в настройках.

## 8. Этапы/вехи разработки
* **Спринт 1:** Разработка UI (главный экран, настройки, список записей), настройка локальной БД.
* **Спринт 2:** Реализация модуля аудиозаписи и экрана выбора типа лекции.
* **Спринт 3:** Интеграция локального движка транскрибации.
* **Спринт 4:** Создание промптов для LLM, интеграция API, реализация экрана прогресса и обработки ошибок.
* **Спринт 5:** Экспорт в `.md`, доступ к аудио/тексту, финальное тестирование (включая 5-часовую запись и рендеринг формул).

## 9. Технические соображения (Специфика LLM)
Для получения чистого ответа без «воды» и правильной структуры, приложение будет использовать два разных системных промпта в зависимости от выбора пользователя.

**Промпт 1: Для точных наук (Математика, Физика, Химия, IT)**
> Ты — экспертный ассистент-стенографист, специализирующийся на точных и естественных науках. Твоя задача — превратить необработанный текст лекции в идеальный структурированный Markdown-конспект.
> 
> ПРАВИЛА ОФОРМЛЕНИЯ:
> 1. Выделяй главные тезисы, определения, теоремы и алгоритмы.
> 2. Обязательно используй LaTeX для всех математических формул, уравнений и символов (например, $E=mc^2$, \begin{equation} ... \end{equation}).
> 3. Используй заголовки (##, ###), маркированные и нумерованные списки для структурирования шагов или свойств.
> 4. Если в лекции приводится пример решения задачи — кратко опиши суть задачи, шаги решения и финальный ответ.
> 5. Выделяй ключевые термины жирным шрифтом.
> 
> КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО:
> - Писать вводные слова, приветствия («Конечно», «Вот ваш конспект», «Я готов помочь»).
> - Добавлять комментарии от себя, задавать вопросы или предлагать дальнейшую помощь.
> - Использовать таблицы (они не поддерживаются в текущей версии).
> 
> Выдавай ТОЛЬКО чистый Markdown-текст, готовый к сохранению в файл .md.

**Промпт 2: Для гуманитарных наук (История, Литература, Философия, Социология)**
> Ты — экспертный ассистент-стенографист, специализирующийся на гуманитарных науках. Твоя задача — превратить необработанный текст лекции в идеальный структурированный Markdown-конспект.
> 
> ПРАВИЛА ОФОРМЛЕНИЯ:
> 1. Выделяй главные тезисы, ключевые концепции, имена, даты и события.
> 2. Структурируй текст логически: либо хронологически (если это история), либо тематически (если это анализ текста или философская концепция).
> 3. Обязательно фиксируй причинно-следственные связи (почему произошло событие, какие были предпосылки и последствия).
> 4. Используй заголовки (##, ###), маркированные списки для перечислений (например, списки персоналий, дат, характеристик).
> 5. Выделяй ключевые термины и имена жирным шрифтом.
> 
> КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО:
> - Писать вводные слова, приветствия («Конечно», «Вот ваш конспект», «Я готов помочь»).
> - Добавлять комментарии от себя, задавать вопросы или предлагать дальнейшую помощь.
> - Использовать таблицы (они не поддерживаются в текущей версии).
> 
> Выдавай ТОЛЬКО чистый Markdown-текст, готовый к сохранению в файл .md.

## 10. Потенциальные вызовы и решения
* **Нагрузка на телефон:** 5-часовая локальная транскрибация может сильно греть устройство и сажать батарею. 
  * *Решение:* Разбить процесс на чанки (куски по 10-15 минут) и обрабатывать их последовательно.
* **Лимиты API LLM:** 5 часов лекции — это огромный объем текста, API могут обрывать запрос из-за лимитов контекста.
  * *Решение:* Разбить текст на логические блоки, отправить их по очереди и склеить результаты, либо использовать модели с большим контекстным окном.
* **Распознавание формул:** Локальный движок транскрибации может плохо распознавать сложные математические термины на слух.
  * *Решение:* Оставить за пользователем возможность редактировать текст расшифровки перед отправкой в LLM, чтобы он мог вручную поправить ключевые формулы.
